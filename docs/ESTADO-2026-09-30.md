## 1. Como o código chega à produção (regra nova)

1. Branch por tarefa: `claude/<tarefa>` ou `codex/<tarefa>` (minúsculo — no Windows, `Codex/x` e `codex/x` colidem).
2. PR para `main`, CI verde (jobs `app-gate`, `painel`, `landing`, `worker`, `lint`).
3. Merge na `main`.
4. Deploy **somente a partir da `main`**:
   - worker: `cd worker && npm ci && env -u CLOUDFLARE_API_TOKEN npx wrangler deploy`
   - painel: `cd webapp && pnpm install --frozen-lockfile && pnpm build && npx wrangler pages deploy dist --project-name olli-painel-web --branch main`
   - landing: `cd web && npm ci && npm run build && cd ../site && npx wrangler deploy` (o build consulta `/abacate/config` para decidir a copy do Pix — rode com rede)
   - migrations: arquivo novo em `supabase/migrations/`, aplicado depois do merge (Management API ou MCP), conferido por SELECT.

## 3. Como conferir que está vivo

- `GET https://diagnostico.olliorcamentos.online/` → `ia:"on"`, `ia_pago:"on"`, `ia_saude` (por isolate).
- `GET /abacate/config` → `{pix:true, modo:"producao"}`.
- E-mail: `select status, dispatch_scope, count(*) from public.email_outbox group by 1,2;`
- Funil do login: `select evento, motivo, count(*) from public.auth_funil_eventos group by 1,2;`
- `npm run check:ai-models` (com `OPENROUTER_API_KEY` no ambiente) valida a cadeia ao vivo.
- Funil de receita (depois da migration `20260930120000_funil_receita.sql`): painel `/admin` → seção
  "Funil de receita" (coorte semanal, conversão entre degraus, tempo mediano, sem PII). Por SQL:
  `select * from public.admin_funil_coortes(array['<e-mail do dono>'], 12);` e
  `select * from public.admin_funil_exclusoes(array['<e-mail do dono>']);`. Conta interna/demo sai do funil pelo
  botão "Tirar do funil" no detalhe do usuário (auditado) ou por `insert into public.funil_exclusoes`.
